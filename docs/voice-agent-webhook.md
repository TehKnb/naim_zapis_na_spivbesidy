# Webhook для голосового агента: результат дзвінка кандидату

Після розмови агент повідомляє адмінпанелі, чи підходить кандидату запропонований час співбесіди.

## Запит

```
POST https://naimzapisnaspivbesidy-production.up.railway.app/api/webhooks/voice-agent
Content-Type: application/json
```

```json
{
  "card_id": 12345,
  "confirmed": true,
  "status_id": 31
}
```

| Поле | Обов'язкове | Тип | Значення |
|---|---|---|---|
| `card_id` | так | число або рядок з цифр | ID картки ліда в KeyCRM |
| `confirmed` | так | `true` / `false` | `true` — час підходить, `false` — не підходить |
| `status_id` | ні | число | ID статусу картки після дзвінка. Лише записується в журнал |

Також приймаються:
- `confirmed` у вигляді рядка: `"true"`/`"false"`, `"1"`/`"0"`, `"yes"`/`"no"`, `"так"`/`"ні"`;
- тіло у форматі `application/x-www-form-urlencoded` з тими самими полями.

Заголовки авторизації не потрібні.

## Що відбувається

- **`confirmed: true`**: бронь стає підтвердженою співбесідою. У KeyCRM адмінпанель нічого не змінює, статус картки переводить агент.
- **`confirmed: false`**:
  1. бронь знімається, і місце в сеансі звільняється;
  2. поле «Дата співбесіди» в картці KeyCRM очищається;
  3. звільнене місце отримує лід з пізнішою бронню, якому ще не дзвонили (він у статусі «Відібрано»). Його нова дата одразу записується в картку.

Повторний запит з тими самими даними безпечний.

## Відповідь

Код **200**, якщо запит прийнято:

```json
{
  "ok": true,
  "result": "confirmed",
  "card_id": "12345",
  "message": "Співбесіду підтверджено.",
  "session": { "id": "…", "name": "Групова співбесіда — … — 28 листопада, 10:00", "start_date": "2026-11-28T08:00:00.000Z" }
}
```

| `result` | Значення |
|---|---|
| `confirmed` | Співбесіду підтверджено |
| `already_confirmed` | Її вже підтвердили раніше (повторний запит) |
| `cancelled` | Бронь знято, поле в KeyCRM очищено. Поле `keycrm`: `Synced` або `Failed`; при `Failed` деталі в полі `warning` |
| `already_cancelled` | Бронь уже знято раніше. Якщо минулого разу поле не очистилося, очищення повторюється |
| `no_booking` | Для цієї картки немає активної броні, нічого не змінено |

Інші коди:
- **400** — некоректні дані. У відповіді `{"error": {"code": "VALIDATION_ERROR", "message": "…"}}`. Повторювати той самий запит немає сенсу.
- **503** або **5xx** — тимчасова помилка (наприклад, база недоступна). Варто повторити запит через 1–2 хвилини.

## Перевірка

Усі запити агента, зокрема некоректні, записуються в таблицю `interview_agent_events`: тіло запиту, результат і перенесених лідів.
