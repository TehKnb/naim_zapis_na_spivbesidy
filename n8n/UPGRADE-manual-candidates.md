# Оновлення: ручний запис кандидатів зі статусу «Запросили на 1 тур»

## Що змінилося

На сторінці співбесіди в адмінпанелі з'явилася кнопка **«Додати кандидата»**. Вона відкриває список усіх лідів KeyCRM у статусі **«Запросили на 1 тур» (ID 29)** з пошуком за ім'ям, телефоном і воронкою. Ліди з воронки цієї співбесіди показуються першими.

Після вибору ліда адмінпанель показує підтвердження:
- поточний час співбесіди з KeyCRM і новий;
- попередження, якщо лід уже записаний на іншу співбесіду.

Запис робить таке:
1. Перевіряє, що лід досі у статусі 29, співбесіда не минула і в ній є вільні місця.
2. Скасовує активні записи цього ліда на інші співбесіди (`registration_status = Cancelled`). Якщо та співбесіда була **Full**, вона знову стає **Open**.
3. Створює запис у **Interview Participants** (`Confirmed`, `keycrm_sync = Pending`). Якщо співбесіда заповнилась, вона отримує статус **Full**.
4. **Перезаписує поле співбесіди LD_1027** у картці KeyCRM часом цієї співбесіди, у тому ж форматі, що й workflow бронювання. **Статус картки не змінюється.**
5. Позначає запис `Synced`. Якщо KeyCRM відповів помилкою, запис позначається `Failed` з текстом у `sync_error`, а адмінпанель показує попередження. Такий лід у списку має позначку «Повторити KeyCRM»: повторне додавання створить запис заново і ще раз оновить поле.

Змінено лише **workflow 02**. Нові дії: `candidates` і `addParticipant`. Нові вузли в «Конфіг»:

| Поле | Значення | Призначення |
|---|---|---|
| `KEYCRM_API` | `https://openapi.keycrm.app/v1` | Адреса API KeyCRM |
| `CANDIDATE_STATUS_ID` | `29` | Статус лідів для ручного запису («Запросили на 1 тур») |
| `INTERVIEW_FIELD_UUID` | `LD_1027` | Поле часу співбесіди |
| `INTERVIEW_FIELD_TYPE` | `datetime` | Тип поля (як у workflow 01) |
| `CANDIDATES_MAX_PAGES` | `10` | Максимум сторінок по 50 лідів (до 500 лідів) |

Workflow 00, 01, 03, 04 і 05 не змінились, нових таблиць і колонок не потрібно.

## Порядок дій

1. **Резервна копія.** Відкрийте поточний workflow 02 → «…» → **Download**.
2. **Імпорт.** Імпортуйте `02-admin-api-session-management.json`.
3. **Креди:**
   - вузол **Admin API Webhook** — «Admin API secret (X-Webhook-Token)»;
   - чотири вузли KeyCRM — Bearer Auth credential з API-ключем KeyCRM (той самий, що у вузлі «KeyCRM: оновити картку» workflow 01): **KeyCRM: ліди (стор. 1)**, **KeyCRM: ліди (інші сторінки)**, **KeyCRM: картка (add)**, **KeyCRM: записати час співбесіди**.
   - Якщо n8n пише «uses invalid credential», у вузлі лишився порожній credential іншого типу — видаліть вузол і вставте заново з цього файлу або виберіть credential заново.
4. **«Конфіг».** Перенесіть свої значення (`PIPELINES` тощо) і перевірте нові поля з таблиці вище.
5. **Активація.** Деактивуйте старий workflow 02 і активуйте новий. Адреса webhook та сама: `/webhook/session-management`.
6. **Адмінпанель.** Задеплойте нову версію або перезапустіть `npm run dev`. Змінних середовища додавати не треба.

## Як перевірити

1. Відкрийте майбутню співбесіду з вільними місцями → **«Додати кандидата»**. З'явиться список лідів у статусі «Запросили на 1 тур».
2. Оберіть тестового ліда → **«Записати»**. Очікуваний результат:
   - кандидат з'явився в таблиці «Кандидати» зі статусом `Confirmed / Synced`;
   - у картці KeyCRM поле співбесіди містить час цієї співбесіди, а статус не змінився;
   - якщо лід був записаний на іншу співбесіду, там його запис `Cancelled`, а місце звільнилось.
3. Повторно відкрийте список: лід позначений «Уже записаний», і вибрати його не можна.

## Обмеження

- KeyCRM дозволяє 20 запитів на хвилину. Одне відкриття списку — це 1 запит на кожні 50 лідів, один запис кандидата — 2 запити.
- Записати кандидата на співбесіду, що минула або заповнена, не можна. Спочатку збільште максимальну кількість учасників.
