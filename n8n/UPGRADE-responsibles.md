# Оновлення: відповідальні за співбесіди і щоденне нагадування в Discord

## Що змінилося

**Нова таблиця Interview Responsibles** — співробітники, яких можна призначати відповідальними:
- `employee_id` (Number): ID співробітника в KeyCRM. За ним сесія пам'ятає відповідальних;
- `name` (String);
- `discord_id` (String): ID користувача Discord для тегу `<@…>`. Може бути порожнім.

**Interview Sessions**: нова колонка `responsible_ids` (String). У ній ID відповідальних через кому, наприклад `13,39`.

**Workflow 02 (API адмінпанелі)**
- Нова дія `responsibles` повертає список співробітників для форми. Discord ID назовні не віддається, лише ознака, чи він є.
- `create` і `update` приймають `responsibleIds` (масив ID). Відповідальних необов'язково призначати, і їх можна змінювати будь-коли, навіть коли на співбесіду вже є записи.
- У кожній сесії відповідь містить `responsibleIds` і `responsibles` (з іменами).
- Якщо таблиці Interview Responsibles ще немає, API працює як раніше, а форма показує, що список не завантажився.

**00**: для нових інсталяцій створює всі три таблиці.
**04** (новий, одноразовий): створює Interview Responsibles і заповнює її співробітниками.
**05** (новий): щодня о 9:00 надсилає в Discord сьогоднішні співбесіди з тегами відповідальних.

**01 і 03 не змінилися**, їх не перевстановлюйте.

## Порядок дій

### 1. Резервна копія
У n8n відкрийте поточний workflow 02 → «…» → **Download**.

### 2. Таблиця відповідальних
1. Імпортуйте `04-setup-responsibles.json`.
2. Натисніть **Execute workflow**. З'явиться таблиця **Interview Responsibles** з 10 співробітниками.
3. Перевірте таблицю в Data tables. Після цього workflow 04 можна видалити.

Повторний запуск безпечний: він додає лише тих, кого ще немає. Нового співробітника можна просто додати рядком у таблицю. Discord ID вписуйте **як текст**, бо довгі числа n8n і JavaScript округлюють.

### 3. Нова колонка в Interview Sessions
n8n → **Data tables** → **Interview Sessions** → «+» (Add column): `responsible_ids`, тип **String**. Назва саме така, малими літерами.

### 4. Workflow 02 (API)
1. Імпортуйте `02-admin-api-session-management.json`.
2. У вузлі **Admin API Webhook** виберіть credential «Admin API secret (X-Webhook-Token)».
3. Перенесіть у «Конфіг» свої значення, якщо змінювали їх, зокрема `PIPELINES`.
4. Деактивуйте старий workflow 02 і активуйте новий. Адреса webhook та сама: `/webhook/session-management`.

### 5. Workflow 05 (Discord)
1. Discord → налаштування каналу → **Інтеграції** → **Webhooks** → New Webhook → **Copy Webhook URL**.
2. Імпортуйте `05-discord-daily-interviews.json`.
3. У вузлі **Discord: надіслати повідомлення** замініть URL `https://discord.com/api/webhooks/ВСТАВТЕ_ID/ВСТАВТЕ_TOKEN` на свій.
4. Необов'язкові налаштування в «Конфіг»:
   - `SEND_WHEN_EMPTY`: `true` — у дні без співбесід писати «Сьогодні співбесід немає» (за замовчуванням нічого не надсилається);
   - `INCLUDE_CLOSED`: `false` — не показувати закриті співбесіди (за замовчуванням вони є з позначкою «🔒 закрита»);
   - `ADMIN_PANEL_URL`: адреса адмінпанелі, наприклад `https://….up.railway.app`, тоді до кожної співбесіди додається посилання.
5. Перевірте кнопкою **Execute workflow** (тригер «Запустити вручну (тест)»). Повідомлення прийде, лише якщо сьогодні є співбесіди.
6. Активуйте workflow. Час 9:00 рахується за Києвом (часовий пояс workflow — Europe/Kyiv).

Приклад повідомлення:

```
📅 **Співбесіди на сьогодні (середа, 11 листопада)** — 2

🕒 **14:00** · Менеджер з продажу 1 етап
👥 Записано: 7 з 10
👤 Відповідальні: <@1567574546117038182>, <@729036900181999628>

🕒 **16:30** · Рекрутер 1 етап
👥 Записано: 3 з 10
👤 Відповідальні: **Ольга Рішняк**
```

У Discord `<@…>` перетворюється на тег, і людина отримує сповіщення. Співробітник без Discord ID показується жирним ім'ям. Сесія без відповідальних позначається «⚠️ не призначено». Повідомлення довші за 2000 символів діляться на кілька.

### 6. Адмінпанель
Змінних `.env.local` додавати не треба. Після оновлення n8n перезапустіть `npm run dev` (або задеплойте нову версію).

## Як перевірити
1. **Адмінпанель → «Створити співбесіду».** У формі є блок «Відповідальні» з 10 співробітниками; можна обрати кількох.
2. **Збережіть.** Відповідальні з'являться на картці, у списку («Усі співбесіди»), на сторінці співбесіди, а в таблиці — у колонці `responsible_ids`.
3. **Пошук** в «Усіх співбесідах» знаходить співбесіди за ім'ям відповідального.
4. **Discord.** Створіть співбесіду на сьогодні (пізніше за поточний час) і запустіть workflow 05 вручну. У каналі з'явиться повідомлення з тегами.
