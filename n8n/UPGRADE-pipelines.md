# Оновлення: сесії для всіх воронок найму 1 етапу

## Що змінилося

**Workflow 01 (бронювання)**
- Поле `pipeline` у webhook тепер обов'язкове, як `id`, `contact_name` і `contact_phone`. Якщо воно порожнє, спрацьовує алерт «не заповнені поля».
- Сесії шукаються лише тієї воронки, з якої прийшов кандидат: `pipeline_name` у таблиці має дорівнювати полю `pipeline` з webhook (точний збіг, пробіли на краях обрізаються).
- Картка KeyCRM більше не переводиться в інший статус. PUT надсилає лише поле `LD_1027`, і кандидат лишається у «Відібрано». `TARGET_STATUS_ID` прибрано з «Конфіг».
- Алерт «немає вільних сесій» тепер містить назву воронки.
- Повтор оновлення KeyCRM: вивести картку зі статусу «Відібрано» і повернути назад. Workflow знайде наявне бронювання і лише оновить поле.
- Решта логіки без змін: дублі, гонка за останнє місце, Full, Synced / Failed.

**Workflow 02 (API адмінпанелі)**
- У «Конфіг» є нове поле `PIPELINES`: довідник воронок у форматі JSON `[{ "id": 1, "name": "…" }]`. З нього адмінпанель бере список для форми і фільтрів.
- Нова дія `pipelines`.
- `create` і `update` приймають `pipelineId` і перевіряють його за довідником. У сесії зберігаються `pipeline_id` і `pipeline_name`.
- Воронку сесії можна змінити, лише поки на неї ніхто не записаний (`409 PIPELINE_LOCKED`). Сесії без воронки її можна призначити завжди.
- Автоназва тепер з воронкою: «Групова співбесіда — Менеджер з продажу 1 етап — 12 листопада, 14:00».

**00**: створює таблицю сесій одразу з новими колонками (для нових інсталяцій).
**03**: новий одноразовий workflow, що заповнює воронку для наявних сесій.

## Порядок дій

### 1. Резервні копії
У n8n відкрийте поточні workflow 01 і 02 → «…» → **Download**. Збережіть файли, наприклад у `n8n/backup/`. Запишіть свої значення з вузлів «Конфіг», якщо міняли їх.

### 2. Нові колонки в Data Tables
Вузол Data Table не вміє додавати колонки, тому це робиться вручну.
n8n → **Data tables** → **Interview Sessions** → додати колонку (кнопка «+» / Add column праворуч від останньої колонки):
- `pipeline_id`, тип **Number**;
- `pipeline_name`, тип **String**.

Назви саме такі, малими літерами. Не створюйте копій таблиці з назвою, що містить «Interview Sessions»: workflow шукають таблицю за назвою.
Interview Participants не змінюється.

### 3. Прив'язати наявні сесії до воронки
Усі наявні сесії були для «Менеджер з продажу 1 етап». Без воронки бронювання їх не знайде. Є два способи:
- **Workflow 03.** Імпортуйте `03-migrate-session-pipeline.json` і натисніть **Execute workflow**. Він заповнить `pipeline_id = 1` і `pipeline_name = Менеджер з продажу 1 етап` лише там, де воронки ще немає. Після цього workflow можна видалити.
- **Вручну.** Вписати ці два значення в таблиці.

Назви старих сесій лишаються без змін. Нова назва з воронкою з'явиться після редагування сесії в адмінпанелі.

### 4. Імпорт workflow 02 (API)
1. Імпортуйте `02-admin-api-session-management.json`.
2. У вузлі **Admin API Webhook** виберіть credential «Admin API secret (X-Webhook-Token)».
3. У «Конфіг» перевірте `PIPELINES`. Назви мають **символ у символ** збігатися з назвами воронок у KeyCRM, тому найкраще скопіювати їх з KeyCRM. Особливо перевірте «РРС-спеціаліст 1 етап» (у файлі «РРС» набрано кирилицею) і «SMM маркетолог 1 етап» (латиницею).
4. Деактивуйте старий workflow 02 і опублікуйте (активуйте) новий. Адреса webhook та сама: `/webhook/session-management`.

### 5. Імпорт workflow 01 (бронювання)
1. Імпортуйте `01-booking-keycrm-datatables.json`.
2. Виберіть креди:
   - **KeyCRM Webhook**: «Webhook secret (X-Webhook-Token)»;
   - **KeyCRM: оновити картку**: «KeyCRM API (Bearer)».
3. Перенесіть свої значення в «Конфіг», якщо вони відрізнялися. `TARGET_STATUS_ID` більше не потрібен.
4. Деактивуйте старий workflow 01 і активуйте новий. Адреса webhook та сама: `/webhook/keycrm-candidate-booking`.

> Якщо після імпорту n8n продовжує виконувати стару версію, перезапустіть n8n.

### 6. KeyCRM
1. **Поле LD_1027.** Додаткове поле прив'язується до вибраних воронок. Відкрийте налаштування поля і переконайтеся, що воно ввімкнене в усіх воронках зі списку.
2. **Автоматизація в кожній воронці.** Статус «Відібрано» → дія «Відправити Webhook»:
   - URL: production-адреса webhook n8n `…/webhook/keycrm-candidate-booking`;
   - метод POST;
   - заголовок `X-Webhook-Token` (той самий секрет, що й зараз);
   - тіло: ваш поточний шаблон. У ньому обов'язково має бути `"pipeline": "{{ model.pipeline }}"`, а також `id`, `contact_name`, `contact_phone`.
3. **Старий webhook на статус «Новий»** у воронці «Менеджер з продажу 1 етап» вимкніть.
4. Воронки «Керівник відділу продажу 1 етап» і «Старший менеджер з продажів / Тренер команди 1 етап» поки не мають статусу «Відібрано». Сесії для них створювати можна, а кандидати почнуть надходити, щойно ви налаштуєте для них webhook.

Порядок важливий: спершу кроки 2–5 (n8n), потім webhook у KeyCRM.

### 7. Адмінпанель
Змінних `.env.local` додавати не треба. Після оновлення n8n перезапустіть `npm run dev`.

## Як перевірити (на одній тестовій картці)
1. **Адмінпанель → «Усі співбесіди».** Біля кожної сесії видно воронку, фільтр «Усі воронки» працює.
2. **Створіть тестову сесію** у воронці, наприклад «Рекрутер 1 етап», на найближчі дні.
3. **Тестова картка у воронці «Рекрутер 1 етап» → «Відібрано»:**
   - в Interview Participants з'явився запис для сесії з п. 2, `keycrm_sync = Synced`;
   - у картці заповнене поле співбесіди (LD_1027);
   - **статус картки лишився «Відібрано»**.
4. **Ізоляція.** Картка з воронки, у якій немає сесій → в Executions спрацьовує алерт «Немає відкритих майбутніх сесій … у воронці «…»». Запису учасника немає, картка не змінилася. Сесії інших воронок не зачіпаються, навіть якщо в них є місця.
5. **Повторний webhook.** Та сама картка знову у «Відібрано» → «Пропущено: вже оброблено».
6. **Адмінпанель.** Спробуйте змінити воронку сесії, де вже є кандидат. Поле заблоковане, а API відповідає помилкою.

Якщо PUT у KeyCRM поверне помилку, текст буде в `sync_error` (Interview Participants) і в Executions. За специфікацією KeyCRM (`PUT /pipelines/cards/{cardId}`) усі поля тіла необов'язкові, тож тіло лише з `custom_fields` допустиме. Остаточно це підтвердить тест на картці.
